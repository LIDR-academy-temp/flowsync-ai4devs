# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

FlowSync is a two-package repo with no root `package.json` or workspace tooling — run every command from inside `backend/` or `frontend/`, each with its own `node_modules` and lockfile.

- `backend/` — AdonisJS 7 JSON API (API starter kit): Lucid ORM on SQLite (`better-sqlite3`), VineJS validation, token auth, Japa tests.
- `frontend/` — React 19 + Vite 8 + TypeScript SPA: Tailwind v4 + shadcn/ui, `react-router`. Implements signup, login and the protected profile view against the backend auth API.

## Commands

### Backend (`cd backend`)

First-time setup after a clean clone:

```sh
npm install
cp .env.example .env
node ace generate:key        # fills APP_KEY, which is empty in .env.example
node ace migration:run       # creates tmp/db.sqlite3 and regenerates database/schema.ts
```

- `npm run dev` — dev server with HMR on `http://localhost:3333`
- `npm test` — all Japa suites; `node ace test unit` / `node ace test functional` for one suite
- Single test: `node ace test --files=tests/functional/foo.spec.ts` or `node ace test --tests="test title"`
- `npm run lint`, `npm run typecheck`, `npm run format` (Prettier, `@adonisjs/prettier-config`)
- `npm run build` — production build into `build/`
- Scaffolding: `node ace make:controller|model|migration|validator|transformer …`

### Frontend (`cd frontend`)

- `npm run dev` — Vite dev server on `http://localhost:5173`
- `npm run build` — `tsc -b && vite build`
- `npm run lint` — oxlint (not ESLint)
- `npm run format` — Prettier with the same `@adonisjs/prettier-config` as the backend. A `PostToolUse` hook in `.claude/settings.json` already runs it on every `frontend/` file Claude writes or edits.
- Add shadcn/ui components with `npx shadcn@latest add <name>` (config in `components.json`, style `radix-nova`). They land in `src/components/ui/` as generated code; the `only-export-components` lint warning in `button.tsx` comes from shadcn.

There is no frontend test runner configured.

## Frontend architecture

- **`@/` alias** → `src/` (declared in `tsconfig.json`, `tsconfig.app.json` and `vite.config.ts`). Use it instead of relative imports.
- **Backend access.** In dev, Vite proxies `/api` to `http://localhost:3333`, so calls are same-origin and the backend must be running. `VITE_API_URL` (optional, backend origin) overrides that for other environments; a cross-origin `VITE_API_URL` also needs that origin in the `config/cors.ts` allowlist, which is empty in production. All calls go through `src/lib/api.ts`, which unwraps `{ data }` and throws `ApiError { status, errors[] }` (status `0` = network failure). `fieldErrors()` maps 422 validation errors to form fields, with Spanish copy per VineJS rule (`RULE_MESSAGES`).
- **Session.** `src/auth/auth-context.tsx` (`AuthProvider`/`useAuth`) keeps the opaque access token in `localStorage` (`flowsync.token`). `RequireAuth` guards protected routes. A 401 from the API should call `clearSession()`, which bounces the user to `/login`.
- **Routes** (`src/App.tsx`): `/login`, `/signup`, `/profile` (protected). Any other path redirects to `/profile`. UI copy is in Spanish.

## Backend architecture

Things that span several files and are easy to miss:

- **Subpath imports.** Code imports via `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#start/*`, `#generated/*`, etc. (defined in `backend/package.json` `imports`). Use these, not relative paths.
- **Generated code — do not edit by hand.**
  - `database/schema.ts` is generated from the migrations by `node ace migration:run`. It holds `*Schema` base classes with all `@column` declarations. Models extend them (`class User extends compose(UserSchema, …)`) and only add behavior: mixins, relations, computed getters. Change columns with a new migration, not by editing the model or `schema.ts`. Column-type overrides go in `database/schema_rules.ts`.
  - `.adonisjs/server/controllers.ts` (the `controllers` map used in `start/routes.ts`) and `.adonisjs/client/registry/*` (Tuyau typed route registry) are regenerated by the `adonisrc.ts` init hooks (`indexEntities`, `generateRegistry`) whenever the dev server, build or tests boot. A new controller becomes `controllers.<Name>` without manual registration.
- **Routes** (`start/routes.ts`) are all under `/api/v1`. They use `[controllers.X, 'method']` lazy references and named groups (`.as('auth')`, `.as('profile')`). Route names (e.g. `auth.new_account.store`) feed the Tuyau registry and the typed Japa API client in `tests/bootstrap.ts`.
- **Response shape.** `providers/api_provider.ts` adds `ctx.serialize()`, which wraps every payload as `{ data: … }` and validates Lucid paginator metadata. Controllers return `serialize(XTransformer.transform(model))`. Transformers in `app/transformers/` (subclasses of `BaseTransformer`, using `this.pick`) are the public output contract, so never return raw models. `serialize.withoutWrapping()` skips the wrapper.
- **Auth.** The default guard is `api` (opaque access tokens stored in `auth_access_tokens`, `User.accessTokens = DbAccessTokensProvider.forModel(User)`). Signup and login return `{ user, token }`. Protected routes use `middleware.auth()` from `start/kernel.ts`. A `web` session guard is configured but unused.
- **Middleware.** `force_json_response_middleware` makes every response (including errors) JSON. CORS allows all origins in dev and none in production until `config/cors.ts` gets an allowlist (`CORS_ORIGIN` in `.env.example` is a placeholder and is not read anywhere yet).
- **Env.** Every new env var must also be declared in `start/env.ts`, which validates them at boot. `.env.test` overrides values for tests (`SESSION_DRIVER=memory`).
- **Tests.** Suites are defined in `adonisrc.ts`: `tests/unit/**/*.spec.ts` (2s timeout) and `tests/functional/**/*.spec.ts` (30s timeout; HTTP server started automatically). Plugins: assert, api-client (+ session and auth helpers such as `.loginAs(user)`), and Lucid DB assertions. No spec files exist yet.
- **`backend/tmp/`** holds the SQLite DB. Only `tmp/.gitkeep` is tracked. The root `.gitignore` uses `**/tmp/*` (not `**/tmp/`) so that the `.gitkeep` exception keeps working; keep it that way, or migrations fail on a clean clone.

## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
